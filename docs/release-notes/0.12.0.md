## Circular-blocker warning in doctor

`looper doctor` warns when a blocked task's resume condition requires
the same task to start, finish, or become unblocked. The finding names
the task, the condition, and the action: record an independent
prerequisite or correct the task state. The warning never changes the
backlog. Conditions that name another task, or mention the current
task only after an external prerequisite, stay silent.

## Timed provider quota reporting

Agent failures that combine `Request rejected (429)` with a usage
limit and a reset time now report as timed quota failures instead of
configuration failures. The diagnostic retains the provider's reset
text, keeps the provider's timestamp when no time zone is given, and
names the resume or requeue action. Quota failures retain work and
schedule no automatic retry; the controller pauses the profile,
requeues when the window passes, tolerates clocks that are already
past by a small margin, and re-arms the pause after a restart.
Invalid credentials and ordinary rate limits keep their existing
classification.

## Review cost control

Milestone reviews record their coverage. When nothing relevant
changed, the next cycle skips the review agent; when the change sits
outside `source_files` and the goal is closed, the cycle runs a
focused pass over the changed paths only. Repeated unchanged findings
escalate one operator decision per target instead of rediscovering at
full cost. `--once` exits an idle complete run.

## Finding reconciliation

Review findings can now carry a guarded transition: `resume` returns
an idle blocked task whose condition is satisfied, `complete` closes a
task whose outcome already exists, and `reassign` proposes an
ownership correction. Every transition names its revision and target,
never touches fields outside the task contract, and never reopens
completed work. Operator gates and deferrals escalate into one
`reconcile-<task>` decision task instead of applying silently.

## Grouped cleanup warnings

Repeated identical cleanup failures now produce one initial warning
plus a bounded summary with the correct repeat count, per artifact,
for the controller session. Read and lease warnings join the same
groups. A different artifact or error gets its own warning, and a
later success still clears the lease.

## Compact status in agent examples

Agent-facing help, contracts, and monitoring examples use
`looper status --contract v2 --json` and link to `--full` for callers
that need the complete state. Plain `looper status --json` keeps its
format.

## Smaller fixes

- A tracked schema can ride along at the control-file path instead of
  always being excluded (T117).
- `looper config --show` no longer runs the settings line into the
  next sentence (T133).
- Circular-condition detection also catches wording that describes
  circularity without the task's own ID (T140).
- A task file the operator supplies while the startup bootstrap runs
  is preserved instead of overwritten (T144).
- The controller commit identity is no longer hardcoded; tests and
  builds can parameterize it (T151).
- `scripts/scrub-check.py` guards the 2026-11-19 history scrub in
  live tree content, and `scripts/go-test-timeout.sh` prints the
  host's `go test` panic budget.

## History scrub

On 2026-11-19 the repository history was rewritten to remove private
project names, machine paths, and personal identities. Project names
became neutral codenames, machine home paths became generic, and every
commit author became `nibzard <nibzard@users.noreply.github.com>`.
Source archives for tags before this release therefore changed; the
Homebrew formula pins this release. Public provider identifiers in the
pricing catalog are unchanged.

Validation: `make test` passes on this tree, including the Go suite,
`go vet`, installer and build checks, the runtime fixtures, package
smoke, and skill checks. The tests use local agent fixtures. No paid
agent calls are required.
