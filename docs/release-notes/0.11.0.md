# Looper 0.11.0

This release ships the operator workflows: checked publication, fresh
requeue, headless configuration, and structured blocker reasons. A
controller started before the upgrade keeps its old build, contract
surface, and request types until it restarts.

## Publish accepted work

- `looper publish --preview` composes the exact project commit from a
  stopped run's accepted tree, runs every guard, and binds a
  content-sensitive token. The preview is read-only.
- `looper publish --apply --token <token>` re-verifies the token under the
  repository and index locks, writes one project commit with the current
  `HEAD` as parent, advances the branch by compare-and-swap, installs the
  prepared index, and reconciles the saved baseline. A stale token is
  refused without changing anything.
- Hooks do not run, because the commit is written from an immutable tree.
  Identity and signing follow your Git configuration. The preview states
  both facts.
- A journal carries every crashed publication to completion or a preserved
  conflict. Startup resolves it before any comparison runs.
- See [recovery](../recovery.md) for the commit contents and the
  crash boundaries.

## Fresh requeue

- `looper requeue <task-id> --fresh` retires every reusable attempt as
  evidence and returns the task to `todo` under its original ID. The next
  dispatch creates a new attempt under the current worker role, so you can
  switch providers without losing history. Dependents stay connected.
- `--preview` reports what a fresh application would retire, read-only.
- Fresh mode is a `requeue-fresh` request. A controller that does not
  advertise it is refused before queueing, so an older controller never
  downgrades fresh mode to an ordinary retry.
- The dashboard requeue dialog gains **[f] Start fresh**.
- See [runtime requests](../runtime-requests.md) for the provider-switch
  example.

## Headless configuration

- `looper config --show`, `--preview`, `--set <key=value>`, and
  `--unset <key>` work without a terminal. `--show` and `--preview`
  create nothing.
- Project scope takes `worker`, `reviewer`, `jobs`, `model`,
  `claude_model`, `effort`, `verify_command`, `setup_command`, and
  `review_every`. Machine scope takes `worker`, `reviewer`, and
  `agents.<name>.adapter|command|model|effort`, works outside a Git
  repository, and supports `--if-revision <digest>` for a
  compare-and-swap edit.
- The whole patch validates before the first write. Each field reports its
  outcome and application boundary. Machine edits apply to a running
  controller only after it restarts.
- Stopped project edits journal beside `profile.json`, so an interrupted
  save completes or reports on the next attempt, and a repeated `--set`
  replays to the same result.
- Version 2 serves `contracts/schemas/v2/config.schema.json`. See
  [agent profiles](../AGENT-PROFILES.md).

## Structured blocker reasons

- Blocked tasks carry one optional `block_reason`: class (`operator`,
  `deferred`, `failure`, `unknown`), a bounded code, retry guidance, and
  the attempt it references. Control tags stay authoritative; blocker text
  is never parsed for the class.
- Version 2 doctor findings, status findings, and compact inspection carry
  the reason. Operator and deferred findings downgrade to informational
  severity, so a monitor can tell expected waiting from execution failure.
- See [observability](../observability.md) for the monitor policy table.
- `looper amend` can correct reason metadata on an idle blocked task.

## Migration and downgrade limits

- The task file gains the optional `block_reason` field. The schema
  version stays 1. Older Looper binaries decode the file and ignore the
  field. An external validator pinned to the pre-extension schema may
  reject it; Looper does not claim new metadata validates on every older
  strict reader.
- Legacy JSON output is byte-identical. `block_reason` and the reason
  fields appear only in version 2 documents and the task file.
- `publish`, `requeue --fresh`, and headless `config` version 2 documents
  are new. Callers that stay on the legacy contract see the plain text
  renderings.
- `looper version --contract v2` lists the new client commands
  (`publish`, `requeue`) and request types (`requeue-fresh`) a new
  controller advertises.
