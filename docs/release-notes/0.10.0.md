# Looper 0.10.0

This is the first published release since 0.8.3. Version 0.9.0 was
prepared but never published, so its changes also ship here. See
[0.9.0](0.9.0.md) for those notes.

## Changes that affect existing users

- Claude is the default coding agent. Before, the silent default was
  Codex. A start with no saved profile and no `--agent` prints a notice
  that names the agent.
- A new project runs the agent setup on its first interactive start. A
  new unattended project needs `--agent`, a saved choice, or `--yes`.
  Projects with a saved profile keep their settings.
- A controller started before the upgrade keeps its old build, contract
  surface, and request types until it restarts. Installing the binary
  does not update a running controller. `looper status` and
  `looper doctor` now report the difference.

## Agent profiles

- `looper config` names agent commands as profiles. Each profile binds
  an executable to an adapter (Claude Code, Codex, or Zcode) with an
  optional model and effort.
- Worker and reviewer roles select profiles independently. For example,
  `looper --agent glm --review-agent anthropic`.
- Saving configuration runs no agents. `looper config --test-agent
  <name>` runs an explicit live check that uses model credits.
- Invocation records name the profile, adapter version, executable,
  model, and effort. See [agent profiles](../AGENT-PROFILES.md).

## Commands for people and coding agents

- `looper add-task`, `looper cancel`, and `looper amend` change the
  backlog of a live run through checked requests. Each request returns
  a receipt. `--idempotency-key` makes a retry safe.
- `looper requests` and `looper wait` report request outcomes. A wait
  has a required, finite timeout.
- `looper recovery --preview` explains a refused start without changes.
  `looper recovery --apply` applies one listed choice.
- `looper runs` lists saved runs. `looper preflight` shows the
  configuration a start would use. No agent runs for either command.
- `looper stop --interrupt` stops a controller at once and keeps partial
  work, like Ctrl+C.
- `looper help <command>` prints the options, documents, and exit codes
  of one command.

## Version 2 contracts stay opt-in

`--contract v2` selects bounded JSON documents with schemas and fixtures
under `docs/contracts/`. The default stays the legacy contract. Legacy
JSON output is byte-for-byte unchanged. See
[agent contracts](../AGENT-CONTRACTS.md) and the
[migration guide](../AGENT-CONTRACT-MIGRATION.md).

## Reliability

- Agent failures report the agent's own error text. Account, billing,
  and quota failures classify as configuration errors and stop retries.
- Bootstrap receives the backlog schema and gets one bounded correction.
- Nil-plan guards close two controller panics seen in live runs.
- Diagnosis and run-recovery agents publish activity and heartbeats.
- Snapshots work in repositories that ignore their own task file.
- Builds after a release report a development version, such as
  `0.10.1-dev.3`, instead of the last release number.

## Documentation

The README is shorter. Reference material moved into pages under
`docs/`: install, dashboard, tasks and checks, agents, recovery,
runtime requests, and observability.

## Known gaps

- On macOS, process identity checks read `/proc`, which macOS does not
  provide. Worker statistics, liveness detection, and
  `looper stop --interrupt` are unreliable there (T019). No runtime
  behavior was tested on macOS. The macOS ARM64 build is a compile
  check only.
- The PTY tests (first-run form, animation, dashboard signals) run on
  Linux only.
- The fresh-agent evaluation of the version 2 contracts is prepared
  and not run (T120). Fixture results are not evidence about real
  agents.
- On 2026-11-13 a 0.9.1-dev.12 controller lost a stop request during a
  review. The cause is unknown. A regression test shows that current
  source drains in the same situation.

Validation: `make test` passes on this tree, including the Go suite,
`go vet`, installer and build checks, all 73 runtime fixtures, package
smoke, and skill checks. `make race` passes, including the runtime
fixtures under the race detector. The legacy byte and shape guards and
the version 2 schema fixtures run in the Go suite. The tests use local
agent fixtures. No paid agent calls are required.
